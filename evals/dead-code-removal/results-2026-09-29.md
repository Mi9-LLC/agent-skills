# dead-code-removal eval results, 2026-09-29

## What was run

All runs used `claude -p` with Claude Code 2.1.285, model `claude-opus-5`, and the skill installed globally at `~/.claude/skills/dead-code-removal`. The trigger runs and the first behaviour runs (scenarios 0, 1 and 3) used the skill at commit `48ebf39`. Scenario 1 run 2 and scenario 3 run 2 used the working tree after the first round of fixes. Scenario 3 run 3 used the working tree after four more fixes. Each run started from a fresh copy of a fixture repository (`with-analysis` for every behaviour run). The fixture repositories are in the session scratchpad and are not committed; the fixture spec in `evals.json` is how to rebuild them. Every result below comes from the stream-json log of its run.

## Trigger results

Recall was 8/8: every positive loaded the skill. Precision was 8/8: no hard negative loaded it. Total cost was about $22 and no run timed out.

The negatives went to these skills: N1, N3, N4 and N8 to none, N2 to `health`, N5 to `session-cleanup`, N6 to `sonar-issue-fix`, N7 to `simplify`. Under `--permission-mode dontAsk` the loads of `health` and `sonar-issue-fix` were denied; the model's choice is still visible in the log, so the result stands.

Four negatives had a fixture that could not fully answer them:

- N4: the named symbol `parseLegacyId` is used in this fixture, so the run stopped because it was used, not because the request was a plain edit.
- N5: a fresh session has no branch or worktree of its own, so the run found nothing to clean up (the same problem as `evals/session-cleanup` P5).
- N6: the fixture has no Sonar configuration or results.
- N8: the fixture has no HTTP endpoint, so the run stayed quiet because the endpoint does not exist. The "runtime evidence" carve-out was not measured. A real `/api/v1/export` handler is needed for that.

## What each failure led to in SKILL.md

- Scenario 0, status lines inside the findings: nothing may be added inside the analysis's findings, and the items of Step 3 are copied word for word into the delegated agent's prompt.
- Scenario 1 run 1, deletion in turn 1: the approval for Step 4 cannot come from the user's first message.
- Scenario 1 run 1, test edit to pass the gate: the eval's trap was redesigned (turn 2 forbids editing `tests/repo/layout.test.ts`); no SKILL.md change.
- A scratch-repo test during the fixes: `git checkout -- <path>` fails on a file deleted with `git rm`, and `git clean -f -- <path>` does not remove a staged new file, so reverts now use `git restore --source=HEAD --staged --worktree -- <path>`.
- Scenario 1, F5 not asked in runs 1 and 2: test-only items are marked in the plan, then asked as questions.
- Scenario 1 run 2, `git add -A -n` and a commit message that began with `@`: no `git add -A` in any form, and commit messages use a heredoc in POSIX shells.
- Trigger run P6, worktree made with `EnterWorktree` in `.claude/worktrees`: use `git worktree add`.
- Scenario 3 run 1, no `AskUserQuestion`: if it is unavailable, ask in the reply and stop.
- Scenario 3 run 2, one branch treated as the answer: only the user's own words answer the base-commit question, never the repository state.
